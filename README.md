# Лабораторная работа №2
## Проектирование информационной системы

**Тема:** Система бронирования рабочих мест (Вариант 11)
**Выполнила:** Монина Анастасия, ИТД-31

## 1. Описание предметной области

Предметной областью является процесс организации гибридного формата работы сотрудников компании. Количество рабочих мест в офисе физически меньше числа сотрудников, поэтому закрепление конкретного стола за конкретным человеком неэффективно. Систeма автоматизирует учёт офисных ресурсов (рабочих мест, зон, оборудования), процесс бронирования места на определённую дату и временной интервал, а также контроль текущей занятости пространства.

**Решаемая проблема:** учёт рабочих мест ведётся вручную или не ведётся вовсе — сотрудники тратят время на поиск свободного стола с нужным оборудованием, возникают конфликты при двойном занятии одного места, а руководство не располагает объективными данными о загруженности офиса.

**Цель системы:** централизованный учёт, бронирование и мониторинг рабочих мест, гарантирующие сотруднику доступ к нужному оборудованию, исключающие накладки и предоставляющие аналитику использования офисного пространства.

**Область применения:** внутрикорпоративная среда компаний, практикующих гибридный формат работы.

**Ключевые сущности** (детально описаны в лабораторной работе №1): Сотрудник, Рабочее место, Бронирование, Офисная зона, Оборудование.

## 2. Пользователи и роли

| Роль | Назначение | Основные задачи | Доступные функции | Уровень доступа |
|---|---|---|---|---|
| **Сотрудник** | Инициатор бронирования, планирует свою работу в офисе | Найти и забронировать место, спланировать присутствие в офисе, найти коллег | Поиск и фильтрация свободных мест; создание, изменение и отмена собственных бронирований; поиск коллег на карте офиса | Базовый — доступ только к своим данным и общей карте офиса |
| **Офис-менеджер** | Администратор физического пространства, следит за состоянием ресурсов | Поддерживать актуальный реестр мест и зон, разрешать конфликты, анализировать загруженность | Добавление/удаление рабочих мест и зон; изменение статуса места и оборудования; принудительная отмена любых бронирований; формирование отчётов о загруженности | Расширенный — управление ресурсами и бронированиями всех сотрудников |
| **Системный администратор** | Технический специалист, обеспечивает работу системы | Поддерживать учётные записи и роли, следить за стабильностью системы | Создание, редактирование и блокировка учётных записей; назначение ролей; мониторинг логов и устранение ошибок | Максимальный — административный доступ ко всей системе |

## 3. Сценарии использования

### Сценарий 1. Поиск и бронирование рабочего места
- **Инициатор:** Сотрудник
- **Шаги:**
  1. Сотрудник открывает раздел «Бронирование» в системе.
  2. Указывает дату и временной интервал, на который нужно место.
  3. Задаёт фильтры: офисная зона, необходимое оборудование.
  4. Система показывает список и интерактивную карту свободных мест, соответствующих условиям.
  5. Сотрудник выбирает подходящее рабочее место.
  6. Система проверяет, что место действительно свободно на выбранный интервал.
  7. Сотрудник подтверждает бронирование.
  8. Система создаёт запись о бронировании и отправляет уведомление на почту.
- **Ожидаемый результат:** рабочее место закреплено за сотрудником на выбранную дату и время, ему приходит подтверждение по email.

### Сценарий 2. Изменение или отмена бронирования
- **Инициатор:** Сотрудник
- **Шаги:**
  1. Сотрудник открывает раздел «Мои бронирования».
  2. Выбирает активное бронирование из списка.
  3. Нажимает «Изменить» или «Отменить».
  4. При изменении — указывает новую дату/время; при отмене — подтверждает действие.
  5. Система проверяет доступность нового интервала (при изменении).
  6. Система обновляет или удаляет запись о бронировании.
  7. Система отправляет уведомление об изменении/отмене на почту сотрудника.
- **Ожидаемый результат:** бронирование обновлено или отменено, место снова доступно для других сотрудников.

### Сценарий 3. Поиск коллеги на карте офиса
- **Инициатор:** Сотрудник
- **Шаги:**
  1. Сотрудник открывает раздел «Карта офиса».
  2. Вводит ФИО коллеги в строку поиска.
  3. Система ищет активные бронирования коллеги на текущую дату.
  4. Система отображает на карте офиса рабочее место, за которым закреплён коллега.
- **Ожидаемый результат:** сотрудник видит расположение коллеги в офисе на текущий день.

### Сценарий 4. Добавление рабочего места или офисной зоны
- **Инициатор:** Офис-менеджер
- **Шаги:**
  1. Офис-менеджер открывает раздел администрирования ресурсов.
  2. Выбирает «Добавить зону» или «Добавить рабочее место».
  3. Заполняет атрибуты: номер, тип, расположение (зона/этаж), характеристики, закреплённое оборудование.
  4. Сохраняет запись.
  5. Система добавляет новый объект в реестр и делает его доступным для бронирования.
- **Ожидаемый результат:** новое рабочее место или зона появляется в системе и доступно сотрудникам для бронирования.

### Сценарий 5. Принудительная отмена бронирования
- **Инициатор:** Офис-менеджер
- **Шаги:**
  1. Офис-менеджер открывает список активных бронирований.
  2. Находит бронирование, которое необходимо отменить (например, место закрыто на ремонт).
  3. Выбирает «Отменить» и указывает причину.
  4. Система удаляет бронирование и освобождает место.
  5. Система отправляет уведомление сотруднику об административной отмене с указанием причины.
- **Ожидаемый результат:** бронирование отменено, сотрудник проинформирован, конфликт устранён.

### Сценарий 6. Управление учётными записями и ролями
- **Инициатор:** Системный администратор
- **Шаги:**
  1. Администратор открывает раздел управления пользователями.
  2. Создаёт учётную запись нового сотрудника или находит существующую.
  3. Назначает пользователю роль (Сотрудник / Офис-менеджер / Системный администратор).
  4. При необходимости блокирует или разблокирует учётную запись.
  5. Система сохраняет изменения и применяет новые права доступа.
- **Ожидаемый результат:** учётная запись создана/обновлена, пользователь получает доступ к системе в соответствии со своей ролью.

## 5. Компоненты системы

| Компонент | Назначение | Взаимодействует с |
|---|---|---|
| **Веб-интерфейс (Frontend)** | Браузерный клиент с интерактивной картой офиса, формами бронирования и дашбордами для разных ролей | Backend / API |
| **Backend / API** | Реализует бизнес-логику: проверку доступности мест, создание/отмену бронирований, разграничение прав доступа | Веб-интерфейс, модуль аутентификации, база данных, модуль уведомлений, модуль отчётности |
| **Модуль аутентификации** | Проверяет учётные данные пользователя и его роль перед выполнением операций | Backend / API |
| **База данных** | Хранит данные о сотрудниках, рабочих местах, зонах, оборудовании и бронированиях | Backend / API, модуль отчётности |
| **Модуль уведомлений** | Формирует и отправляет email-уведомления о создании, изменении и отмене бронирований | Backend / API, корпоративная почта |
| **Модуль отчётности** | Формирует аналитические отчёты о загруженности офисных зон за выбранный период | Backend / API, база данных |

## 6. Диаграмма компонентов

![Диаграмма компонентов](diagrams/architecture.png)

На диаграмме показаны три роли пользователей, обращающиеся к системе через веб-интерфейс по HTTPS. Веб-интерфейс взаимодействует с Backend / API по HTTP (REST API). Backend проверяет права доступа через модуль аутентификации, выполняет SQL-запросы к базе данных, инициирует отправку уведомлений через модуль уведомлений (который передаёт письма по SMTP на корпоративную почту) и обращается к модулю отчётности для получения аналитики о загруженности зон.

## 7. Концепция информационной системы

**Назначение и цель системы:** централизованное управление физическим пространством офиса и организация процесса бронирования незакреплённых рабочих мест в условиях гибридного формата работы.

**Основные возможности:**
- интерактивный поиск и фильтрация свободных рабочих мест по дате, зоне и оборудованию;
- самостоятельное создание, изменение и отмена бронирований сотрудниками;
- автоматическое предотвращение конфликтов — блокировка пересекающихся по времени бронирований одного места;
- поиск коллег на карте офиса;
- административное управление ресурсами (местами, зонами, оборудованием) и учётными записями;
- аналитика загруженности офисных зон;
- автоматические email-уведомления о статусе бронирований.

**Тип системы:** внутрикорпоративное веб-приложение (клиент-серверная архитектура).

**Основные компоненты и их взаимодействие:** пользователи (Сотрудник, Офис-менеджер, Системный администратор) работают через веб-интерфейс, который обращается к Backend / API. Backend реализует прикладную логику и проверку доступа через модуль аутентификации, хранит и извлекает данные из базы данных, инициирует отправку email-уведомлений через отдельный модуль и формирует отчёты о загруженности через модуль отчётности. Такое разделение позволяет независимо развивать каждую подсистему и масштабировать её при росте числа пользователей и офисов.
